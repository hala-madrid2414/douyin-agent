# 智能旅行场景 AI 前端 UI 渲染体系设计文档

## 1. 设计概述

- **业务目标**：为智能旅行场景打造一个具备多轮对话、实时工具调用感知、专属知识库增强（RAG）以及生成式结构化 UI 渲染能力的现代化 AI 对话界面。
- **视觉与交互基调**：轻量化旅行调性、专业可靠、反馈即时、支持全流程透明化。
- **组件选型基准**：
  - **基础组件库**：`Ant Design 5.x`（提供按钮、卡片、时间轴、提示框等通用能力）。
  - **AI 专属交互库**：`Ant Design X`（提供对话气泡、发送区、会话列表等 AI 场景原子组件）。

## 2. AI 返回结果渲染场景详细设计

### 场景一：基础对话与流式响应（常规渲染与 Loading）

- **业务含义**：展示用户提出的旅行问题与 AI 助手基于大模型生成的文本回复，并在生成过程中提供实时视觉反馈。
- **用户交互目标**：让用户清晰区分对话双方，在 AI 思考或输出时减轻用户的等待焦虑，并支持富文本（Markdown）阅读。
- **可视化渲染方案**：
  - **静态展示**：右侧展示用户提问（主色调气泡），左侧展示 AI 回复（无边框纯文本排版），支持列表、加粗等 Markdown 格式排版。
  - **等待态（思考中）**：在发送消息后、收到首字前，AI 侧展示骨架屏或呼吸动画，提示“正在为你规划旅行…”。
  - **流式输出态**：采用打字机效果逐字渲染，页面自动平滑滚动至底部。
  - **控制交互**：在打字机效果输出时，回复下方或输入框区域提供“跳过/停止生成”操作。
- **组件选型**：
  - **对话样式**：用户提问采用 `@ant-design/x` 的 `Bubble` 组件（`placement="right"`），AI 回复采用无边框文本布局（配合左侧头像）。
  - **富文本解析**：`@ant-design/x-markdown` 用于安全渲染 Markdown 文本。
  - **输入控制**：`@ant-design/x` 的 `Sender` 组件。
  - **Loading 占位**：`antd` 的 `Skeleton` 或 `Spin` 组件嵌入回复区域中。

### 场景二：Agent 工具调用与过程感知

- **业务含义**：AI 正在调用外部 API 获取实时数据（如：实时天气、航班动态、景区开放时间）。
- **用户交互目标**：向用户透明化 AI 的工作流，建立信任感，避免用户认为应用卡死。
- **可视化渲染方案**：
  - **调用中**：在当前 AI 回复的顶部或独立作为前置状态栏，展示带动画的工具调用提示（如“正在为你查询青岛实时天气…”）。
  - **调用完成与融合**：状态栏变更为完成状态或收起，工具返回的关键实时数据在 Markdown 文本中以**加粗**或特定高亮色展示。
  - **手动干预**：在回复右下角提供交互按钮，支持用户手动触发该工具数据的重新查询。
- **组件选型**：
  - **状态提示栏**：`Bubble` 的 `header` 属性结合 `antd` 的 `Badge`（处理态）或 `Tag` 组件。
  - **重新调用按钮**：`Bubble` 的 `footer` 属性中嵌入 `antd` 的 `Button`（配置 Reload 图标）。

### 场景三：RAG 知识库增强与来源溯源

- **业务含义**：AI 的回答引用了平台专属的“私有旅行攻略/避坑指南”，而非通用大模型的泛泛而谈。
- **用户交互目标**：突出信息的专业性与独家性，允许用户追溯信息来源。
- **可视化渲染方案**：
  - **文本标记**：在引用的文本段落末尾添加专属的标识（如“【专属旅行攻略】”字样或品牌 Icon）。
  - **视觉差异化**：标记符采用区别于正文的主题色（如 `antd` 的 `blue` 或 `purple`预设色）。
  - **详情悬浮**：鼠标悬停（Hover）标记符时，展示来源文档的简要信息或片段。
- **组件选型**：
  - **溯源标记**：`antd` 的 `Tag` 或 `Typography.Text` 组件（开启主题色）。
  - **悬浮详情**：`antd` 的 `Tooltip` 或 `Popover` 组件。

### 场景四：生成式 UI（结构化数据渲染）

- **业务含义**：针对特定复杂旅行需求（多日行程、推荐清单），将 AI 返回的 JSON 结构化数据转化为直观的交互式 UI。
- **用户交互目标**：提升复杂信息的阅读效率，支持展开/收起、详情跳转等深度交互。
- **可视化渲染方案**：
  - **指令一：`render_travel_plan`** **(行程规划)**
    - **UI 呈现**：左侧带有时间轴节点的纵向列表，支持按“天”折叠/展开。
    - **选型**：`antd` 的 `Timeline` 结合 `Collapse` 组件。
  - **指令二：`render_list`** **(美食/住宿推荐)**
    - **UI 呈现**：图文并茂的卡片网格或横向滑动列表，展示评分、价格区间。
    - **选型**：`antd` 的 `List` 结合 `Card` 组件。
  - **指令三：`render_tips`** **(旅行贴士)**
    - **UI 呈现**：按重要程度（红、黄、绿）分类的胶囊标签组。
    - **选型**：`antd` 的 `Space` 结合多色 `Tag` 组件。
  - **混合渲染策略**：在同一条 AI 回复中，上方先渲染打字机文字，下方动态挂载对应 UI 组件。提供“转为纯文字”切换按钮。

### 场景五：会话沉淀与历史管理

- **业务含义**：管理跨设备的云端历史对话记录，并支持用户标记高价值的旅行规划。
- **用户交互目标**：快速找回历史行程，按需筛选，防止误删。
- **可视化渲染方案**：
  - **侧边栏列表**：按时间轴（今天、昨天、更早）对会话进行分组。
  - **高亮与收藏**：单条消息回复提供“收藏”按钮，侧边栏提供“仅看收藏”的筛选器。
  - **清空确认**：触发清空操作时，必须弹出醒目的二次确认浮层。
- **组件选型**：
  - **会话管理**：`@ant-design/x` 的 `Conversations` 组件。
  - **二次确认**：`antd` 的 `Popconfirm` 或 `Modal` 组件。
  - **筛选控件**：`antd` 的 `Segmented` 或 `Select` 组件。

## 3. 全局异常状态与兜底机制

为保障极端情况下的用户体验，系统需具备完整的 UI 兜底策略：

1. **API 超时/失败异常**：
   - 回复区域内停止流式输出，追加红色的 `antd` `Alert` 或错误图标文案（“暂时无法为你规划行程，请稍后重试”）。
   - 提供“重试”按钮，重新发送上一条消息。
2. **工具调用失败降级**：
   - 若 Agent 工具调用失败，UI 不阻断，状态提示变更为“暂时无法获取实时信息，为你提供基础建议”，随后自动降级为模型直接回答（纯文本渲染）。
3. **生成式 UI 解析错误兜底**：
   - 若返回的 JSON 结构损坏或组件挂载失败，需在组件内捕获错误（Error Boundary）。
   - **静默降级**：自动屏蔽 UI 渲染区，强制显示备用的 Markdown 纯文字解析结果，确保信息不丢失。

## 4. 无障碍（A11y）与前端体验规范

1. **色彩与对比度**：
   - 确保文本（尤其是用户回复的浅色气泡内以及AI无边框纯文本内容）对比度至少达到 **4.5:1**。
   - 避免仅使用颜色来传达信息（如旅行贴士需辅以 Icon：⚠️ 表示警告，ℹ️ 表示提示）。
2. **键盘与焦点管理**：
   - 输入区 `Sender` 支持 `Enter` 发送，`Shift + Enter` 换行。
   - 所有交互按钮（收藏、重新调用、新对话）均需可通过 `Tab` 键获取焦点，并拥有明确的 `focus` 环样式。
3. **ARIA 标签**：
   - 针对纯图标按钮（如历史记录侧边栏的删除图标、消息区域的收藏星标），必须配置清晰的 `aria-label` 属性以支持屏幕阅读器（例如 `aria-label="收藏该条旅行规划"`）。
4. **防抖与动画**：
   - 生成式 UI 组件挂载时，应采用透明度渐变（Fade-in）的平滑过渡效果（150ms-300ms），避免因高度突变导致的视觉闪烁与布局抖动（Layout Shift）。
